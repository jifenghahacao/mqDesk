# Spec：MQDesk 手动消费者创建（Consumer Studio）

## 验收标准（GIVEN / WHEN / THEN）

### 1. 页面入口与布局

#### SC-1.1 导航入口
- **GIVEN** 用户已连接到 RabbitMQ
- **WHEN** 查看左侧 Sidebar
- **THEN** 导航项中出现「消费者」子入口或独立「消费测试」入口，点击进入 ConsumerStudio 视图。

#### SC-1.2 响应式布局
- **GIVEN** 用户进入 ConsumerStudio 视图
- **WHEN** 调整窗口宽度在 960px–1920px 之间
- **THEN** 左侧配置面板与右侧消息列表自适应，不出现水平滚动条或元素重叠。

#### SC-1.3 空状态提示
- **GIVEN** 当前无活跃 RabbitMQ 连接
- **WHEN** 用户进入 ConsumerStudio 视图
- **THEN** 页面展示「请先连接 RabbitMQ」提示，表单不可编辑。

---

### 2. 消费者表单与验证

#### SC-2.1 名称必填
- **GIVEN** 用户未填写消费者名称
- **WHEN** 点击「创建消费者」
- **THEN** 名称输入框边框变红，提示「请输入消费者名称」，不提交。

#### SC-2.2 名称唯一性
- **GIVEN** 当前已存在一个名为 `test-consumer` 的消费者
- **WHEN** 用户再输入同名并创建
- **THEN** 提示「消费者名称已存在」，不创建。

#### SC-2.3 队列必选
- **GIVEN** 用户未选择队列
- **WHEN** 点击「创建消费者」
- **THEN** 队列下拉框边框变红，提示「请选择要消费的队列」，不提交。

#### SC-2.4 队列下拉数据来源
- **GIVEN** 用户已连接 RabbitMQ 且当前 vhost 下有队列 A、B
- **WHEN** 打开队列下拉框
- **THEN** 列表展示 A、B，顺序与队列视图一致。

#### SC-2.5 消息处理模式
- **GIVEN** 用户创建消费者
- **WHEN** 选择「同步」模式
- **THEN** 消费者一次只处理一条消息，队列中未确认消息数为 0 或 1。

#### SC-2.6 异步预取值
- **GIVEN** 用户创建消费者并选择「异步」模式
- **WHEN** 设置预取值为 10 并开始消费
- **THEN** RabbitMQ 一次性最多投递 10 条未确认消息给消费者。

#### SC-2.7 Ack 模式（默认预览模式）
- **GIVEN** 用户创建消费者
- **WHEN** 未修改 Ack 设置
- **THEN** 默认使用手动 Ack，消息到达后进入列表但仍在队列中（只看不消费）。

#### SC-2.8 真实消费模式
- **GIVEN** 用户创建消费者
- **WHEN** 选择「自动 Ack」
- **THEN** 消息到达后自动确认并从队列移除。

### 3. 消息过滤条件

#### SC-3.1 Payload 包含过滤
- **GIVEN** 用户设置 payload 过滤条件为「包含 `order`」
- **WHEN** 队列中同时存在包含/不包含 `order` 的消息
- **THEN** 仅包含 `order` 的消息出现在已消费消息列表。

#### SC-3.2 Payload 等于过滤
- **GIVEN** 用户设置 payload 过滤条件为「等于 `{"type":"test"}`」
- **WHEN** 队列中存在匹配与不匹配的消息
- **THEN** 仅完全匹配的消息出现在列表。

#### SC-3.3 Payload 正则过滤
- **GIVEN** 用户设置 payload 过滤条件为「正则 `^user_\d+$`」
- **WHEN** 队列中存在匹配与不匹配的消息
- **THEN** 仅匹配的消息出现在列表；正则不合法时提示「正则表达式无效」。

#### SC-3.4 Headers 过滤
- **GIVEN** 用户设置 header 过滤条件 `x-request-id = 123`
- **WHEN** 队列中存在带/不带该 header 的消息
- **THEN** 仅 header 匹配的消息出现在列表。

#### SC-3.5 多条件组合
- **GIVEN** 用户同时设置 payload 包含 `order` 和 header `x-type=vip`
- **WHEN** 队列中存在部分匹配和全部匹配的消息
- **THEN** 仅同时满足两个条件的消息出现在列表。

---

### 4. 消费者生命周期

#### SC-4.1 创建后待启动
- **GIVEN** 用户填写表单并点击「创建消费者」
- **WHEN** 表单验证通过
- **THEN** 消费者进入列表，状态为「待启动」，未实际消费消息。

#### SC-4.2 开始消费
- **GIVEN** 消费者处于「待启动」或「已暂停」状态
- **WHEN** 用户点击「开始消费」
- **THEN** 状态变为「运行中」，消息列表开始接收消息。

#### SC-4.3 暂停消费
- **GIVEN** 消费者处于「运行中」状态
- **WHEN** 用户点击「暂停」
- **THEN** 状态变为「已暂停」，不再接收新消息，已投递未确认消息保留。

#### SC-4.4 继续消费
- **GIVEN** 消费者处于「已暂停」状态
- **WHEN** 用户点击「继续」
- **THEN** 状态恢复为「运行中」，继续接收消息。

#### SC-4.5 销毁消费者
- **GIVEN** 用户点击「销毁」
- **WHEN** 确认弹窗后
- **THEN** 消费者断开连接、状态变为「已销毁」并从列表移除；手动 Ack 模式下未确认消息重新入队（保证预览模式不丢消息），自动 Ack 模式下已确认消息已正常消费。

#### SC-4.6 错误状态
- **GIVEN** 消费者运行中 RabbitMQ 连接断开
- **WHEN** 下一次心跳或拉取失败
- **THEN** 状态变为「错误」，展示错误信息，提供「重试」按钮。

---

### 5. 已消费消息列表

#### SC-5.1 消息字段展示
- **GIVEN** 消费者已消费一条消息
- **WHEN** 查看已消费消息列表
- **THEN** 每条消息展示：序号、时间戳、路由键、payload 摘要、headers 摘要、Ack 状态。

#### SC-5.2 Payload 展开查看
- **GIVEN** 消息列表中存在一条消息
- **WHEN** 用户点击该消息
- **THEN** 展开显示完整 payload、headers、exchange、routing_key、redelivered 标志。

#### SC-5.3 手动 Ack 操作
- **GIVEN** 消费者为手动 Ack 模式
- **WHEN** 用户在消息行点击「确认」
- **THEN** 向 RabbitMQ 发送 ack，该消息状态变为「已确认」。

#### SC-5.4 列表清空
- **GIVEN** 消息列表已有 100 条消息
- **WHEN** 用户点击「清空列表」
- **THEN** 前端列表清空，不影响已确认消息。

#### SC-5.5 实时刷新
- **GIVEN** 消费者处于运行中
- **WHEN** 新消息到达
- **THEN** 消息列表在 1 秒内更新， newest 在最上方。

---

### 6. 错误处理与帮助

#### SC-6.1 队列无消费权限
- **GIVEN** 当前用户没有某队列的消费权限
- **WHEN** 用户尝试从该队列消费
- **THEN** 状态变为「错误」，提示「无权限消费该队列：{queue_name}」。

#### SC-6.2 队列被删除
- **GIVEN** 消费者正在运行
- **WHEN** 对应队列被删除
- **THEN** 状态变为「错误」，提示「队列不存在：{queue_name}」。

#### SC-6.3 帮助提示
- **GIVEN** 用户鼠标悬停在「同步/异步」选项上
- **WHEN** 停留超过 500ms
- **THEN** 出现 Tooltip：「同步：逐条处理；异步：并发处理，可设置预取值。」

### 7. 测试与门禁

#### SC-7.1 Rust 测试
- **GIVEN** 新增 consumer manager 和 Tauri 命令
- **WHEN** 运行 `cd src-tauri && cargo test`
- **THEN** 所有测试通过，至少覆盖创建、启动、暂停、销毁四个状态转换。

#### SC-7.2 前端测试
- **GIVEN** 新增 ConsumerStudioView
- **WHEN** 运行 `npm test`
- **THEN** 至少覆盖表单验证、状态渲染、消息列表渲染、空状态。

#### SC-7.3 全量门禁
- **GIVEN** 提交前运行 `python tooling/checks.py guard`
- **WHEN** 检查通过
- **THEN** build / lint / typecheck / test 全部成功，无新增 warning。
