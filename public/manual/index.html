1. 产品概述

1.1 MQDesk 是什么？

MQDesk 是一款桌面版 RabbitMQ 可视化管控工具。

你可以把它理解成一个“消息队列的图形化管理小助手”。它能帮你：

  • 不用记命令，就能连接 RabbitMQ 服务；
  • 一眼看出队列是否堆积、有没有人消费；
  • 像发微信一样发送测试消息；
  • 查看消息发送记录，追踪消息去向；
  • 手动启动消费者，实时查看进入队列的消息内容；
  • 监控连接与信道，排查客户端连接问题；
  • 清空队列、管理绑定规则，完成日常运维操作。

1.2 它能帮你解决什么问题？

场景没有 MQDesk 时有了 MQDesk 后
想查看队列有多少消息要打开英文管理后台，找半天打开软件总览页，数字直接显示
怀疑消息没发出去要写代码测试或查日志点几下就能发一条测试消息
队列消息堆积了看不到，等问题爆发健康状态变红/黄，提前预警
忘了连接密码明文写在配置文件里本地加密保存，更安全
需要清空测试队列写脚本或调接口队列详情页一键 Purge
想看消息被谁消费翻日志、写消费者消费者工作室直接启动并查看

1.3 适合谁用？

  • 刚接触 RabbitMQ 的新手开发者；
  • 需要临时查看/测试消息队列的测试人员；
  • 不想折腾英文管理后台的运维人员；
  • 学习消息队列课程的学生。

2. 安装与初始化

2.1 环境准备

项目要求
操作系统Windows 10/11（64 位）或兼容的 Linux 发行版（如麒麟）
内存至少 4GB
硬盘空间至少 200MB 可用空间
网络能访问你要连接的 RabbitMQ 服务器
依赖组件已内置，无需单独安装
什么是 RabbitMQ？ 它是一种“消息中间件”，负责在不同程序之间传递消息。如果你还没安装 RabbitMQ，可以先让同事或运维给你一个连接地址，再使用 MQDesk。

2.2 安装步骤

第一步：获取安装包

从发布页面下载对应系统的安装文件：

  • Windows： MQDesk_0.1.0_x64-setup.exe
  • 麒麟 / Linux： mqdesk_0.1.0_amd64.deb 或 MQDesk_0.1.0_amd64.AppImage

第二步：运行安装程序（Windows）

  1. 双击安装包；
  2. 如果系统弹出“是否允许此应用对你的设备进行更改”，点击「是」；
  3. 选择安装路径（建议保持默认），点击「下一步」；
  4. 等待安装完成，点击「完成」。

第三步：首次启动

  1. 安装完成后，桌面/开始菜单会出现 MQDesk 图标；
  2. 双击图标启动软件；
  3. 首次启动会弹出主界面。

第一次打开 MQDesk，你会看到「连接管理」页面。此时还没有保存任何连接，点击「新建连接」开始。

4. 功能详解

4.1 连接管理

是什么？

「连接管理」用于保存你要管理的 RabbitMQ 服务地址、用户名、密码等信息。

为什么需要它？

就像微信需要保存账号密码一样，MQDesk 也需要先保存 RabbitMQ 的连接信息，才能帮你查看队列、发送消息。

怎么用？

新建连接

  1. 点击侧边栏「连接」；
  2. 点击右上角「+ 新建连接」按钮；
  3. 在弹出的表单中填写连接信息：
字段填写说明示例
连接名称给这个连接起个名字，方便识别开发环境
主机地址RabbitMQ 服务器地址127.0.0.1 或 mq.example.com
AMQP 端口消息传输端口，默认 56725672
管理端口网页管理接口端口，默认 1567215672
管理协议一般选 httphttp
虚拟空间默认填写 //
用户名RabbitMQ 登录用户名guest
密码RabbitMQ 登录密码guest

图 4-1：新建连接表单

  1. 填写完成后，点击「测试连接」；
  2. 如果提示「已连接：...」，说明信息填对了；
  3. 点击「保存并连接」，软件会自动连接并跳转到总览页。

编辑 / 删除连接

  1. 在连接列表中，点击某个连接卡片；
  2. 点击「编辑」可修改连接信息；
  3. 点击「删除」可删除该连接（会二次确认）。

切换连接

  1. 点击侧边栏「连接」；
  2. 点击想要使用的连接卡片；
  3. 软件会自动连接该 RabbitMQ 服务。

4.2 总览仪表盘

是什么？

「总览」是 MQDesk 的“首页”，用一句话和几个数字卡片告诉你 RabbitMQ 当前整体状态。

为什么需要它？

就像手机健康 App 每天告诉你“步数、睡眠、心率”一样，总览让你不用逐个队列检查，就能快速判断系统是否健康。

怎么用？

连接成功后，软件会自动跳转到总览页，显示以下内容：

区域说明
健康状态横幅一句话总结当前状态
队列总数当前有多少个队列
交换机总数当前有多少个交换机
待消费消息所有队列中等待被消费的消息总数
在线消费者当前有多少个消费者程序在线

图 4-2：总览仪表盘

健康状态说明

颜色状态含义
绿色正常队列有消费者，消息没有堆积
黄色堆积预警某个队列消息数超过 1000，需要关注
红色无人消费队列有消息，但没有消费者处理
灰色空闲队列里没有消息，也没有消费者

自动刷新

总览页默认会自动刷新。你可以在「设置 → 自动刷新」中开启/关闭，或调整刷新间隔。关闭后数字不会自动更新，需要手动切换页面或点击刷新按钮。

4.3 队列列表

是什么？

「队列」页面列出当前 RabbitMQ 中的所有队列，并显示每个队列的健康状态。

为什么需要它？

当你怀疑某个业务出问题（例如订单没处理、短信没发送），可以先看队列列表，快速定位是不是消息卡住了。

怎么用？

  1. 点击侧边栏「队列」；
  2. 页面会显示所有队列，默认按健康状态排序，红色/黄色会排在前面；
  3. 在顶部搜索框输入队列名，可以按名称过滤；
  4. 使用「类型」下拉框可按队列类型（classic / quorum）筛选；
  5. 使用「健康」下拉框可按健康状态筛选；
  6. 点击表头翻页按钮可浏览更多队列。

图 4-3：队列列表——支持搜索、筛选、分页

虚拟滚动与大数据量

当队列数量很多时，列表采用虚拟滚动技术，只渲染当前可见的行，保证首屏加载快、滚动流畅。你无需担心一次性加载几万个队列会卡顿。

查看队列详情

  1. 在队列列表中找到目标队列；
  2. 点击该行；
  3. 进入队列详情页。

4.4 队列详情

是什么？

「队列详情」展示某个具体队列的实时数据，包括消息数量、消费者数量、消息速率、绑定规则等。

为什么需要它？

当你发现某个队列健康状态异常（红色/黄色），需要进入详情页看具体数字，判断问题有多严重。

怎么用？

区域说明
健康状态卡片显示当前队列健康状态
核心指标待消费、处理中、消费者数、消息速率
速率折线图近一段时间的消息流入/流出趋势
绑定规则查看与该队列绑定的交换机及路由键
抓取预览查看队列前几条消息内容，不会真正消费

图 4-4：队列详情页面

抓取预览消息

  1. 在队列详情页找到「抓取预览」区域；
  2. 输入想看的消息数量（默认 10 条）；
  3. 点击「抓取预览」按钮；
  4. 消息内容会显示在下方，原来的消息仍保留在队列中。

4.5 队列清空（Purge）新功能

是什么？

「清空队列」用于删除队列里的所有消息，但保留队列本身。

为什么需要它？

测试环境经常有大量脏数据，Purge 可以一键清理，不用删除队列再重建。

怎么用？

  1. 进入队列详情页；
  2. 点击右上角「清空」按钮；
  3. 在二次确认弹窗中点击「确定」；
  4. 等待几秒，队列消息数会归零。
注意：Purge 会永久删除消息，生产环境请谨慎操作。

4.6 绑定管理（Bindings）新功能

是什么？

「绑定规则」定义了交换机如何把消息路由到队列。在 MQDesk 中，你可以查看某个队列的所有绑定，并删除不再需要的绑定。

为什么需要它？

消息没有进入预期队列时，往往是绑定规则配错了。在这里可以直接看到“哪个交换机通过什么路由键绑到了这个队列”。

怎么用？

  1. 进入队列详情页；
  2. 切换到「绑定」标签页；
  3. 列表会显示 Source（交换机）、Routing Key（路由键）、Arguments（参数）；
  4. 点击某行右侧的「删除」按钮可解绑（会二次确认）。

图 4-5：队列详情中的绑定管理

注意：删除绑定后，交换机将不再把匹配的消息路由到该队列。如果是生产队列，请确认影响后再操作。

4.7 集群节点新功能

是什么？

「集群节点」页面展示 RabbitMQ 集群中每个节点的运行状态、内存使用、磁盘剩余、文件描述符、进程数等核心指标。

为什么需要它？

当整体性能下降或出现告警时，需要先确认每个节点是否健康、资源是否耗尽。

怎么用？

  1. 点击侧边栏「集群节点」；
  2. 页面列出所有节点，绿色表示运行中，红色表示离线；
  3. 查看内存占用、磁盘剩余、运行时长等关键字段；
  4. 如果某个节点状态异常，优先检查该节点的资源使用情况。

图 4-6：集群节点页面

4.8 消费者列表新功能

是什么？

「消费者列表」展示当前所有在线消费者，包括消费者标签、所属队列、客户端地址、连接名称、消息速率、Ack 模式、Prefetch 数量等。

为什么需要它？

队列状态异常时，可以快速判断“到底有没有人在消费这个队列”，以及消费速度是多少。

怎么用？

  1. 点击侧边栏「消费者」；
  2. 列表显示所有活跃消费者；
  3. 在搜索框输入队列名，可筛选出特定队列的消费者；
  4. 通过消息速率判断消费是否健康。

图 4-7：消费者列表页面

4.9 连接与信道监控新功能

是什么？

「连接与信道」页面展示当前连接到 RabbitMQ 的所有客户端，以及每个连接下的信道列表。

为什么需要它？

当你怀疑某个服务没有正确连接，或者连接数过多时，可以在这里看到每个连接的 IP、协议、在线时长、信道数量、消费者数、消息速率等。

怎么用？

  1. 点击侧边栏「连接与信道」；
  2. 页面列出所有活跃连接；
  3. 点击某行连接可展开/折叠，查看该连接下的信道；
  4. 信道信息包括编号、消费者数、Prefetch、发布/投递/确认速率。

图 4-8：连接与信道监控页面

4.10 消费者工作室（Consumer Studio）新功能

是什么？

「消费者工作室」让你不用写代码，就能手动启动一个消费者，实时查看队列里的消息内容。

为什么需要它？

排查问题时，经常需要确认“消息到底长什么样”。在这里启动一个临时消费者，即可看到完整消息体、Headers，并支持手动 Ack。

怎么用？

  1. 点击侧边栏「消费者工作室」；
  2. 在右侧表单填写消费者配置：
字段说明
名称给这个消费者起个名字，方便识别
目标队列选择要消费的队列
模式async（持续消费）或 preview（只查看不确认）
Prefetch每次从 RabbitMQ 取多少条消息到本地，默认 10
自动 Ack开启后消息进入即自动确认；关闭后需要手动 Ack
过滤条件只显示 payload 或 headers 匹配条件的消息
  1. 点击「创建消费者」；
  2. 在列表中点击「启动」；
  3. 当队列有新消息时，左侧消息流会实时显示；
  4. 如需停止，点击「暂停」或「销毁」。

图 4-9：消费者工作室——手动启动消费者并查看消息

提示：预览模式（preview）不会真正消费消息，消息会重新入队，适合排查问题。async 模式会真实消费，请谨慎用于生产队列。

4.11 消息发送

是什么？

「消息」页面用于向 RabbitMQ 发送测试消息，并查看发送历史。

为什么需要它？

当你开发了新功能，想验证“程序能不能收到消息”，或者想模拟某个业务事件时，可以在这里手动发一条消息。

怎么用？

发送一条消息

  1. 点击侧边栏「消息」；
  2. 选择发送模式：
    • 直发模式：直接发送到指定队列；
    • 交换机模式：发送到交换机，由路由键决定去向。
  3. 填写目标队列名或路由键；
  4. 选择消息内容类型（通常选 JSON）；
  5. 填写消息内容；
  6. 点击「发送」。

图 4-10：消息发送页面

查看发送记录

发送成功后，页面下方的消息流会新增一条记录，包含时间、队列、状态、摘要。

4.12 队列消息探查新功能

是什么？

「队列消息探查」用于查看指定队列中当前真实存在的消息内容，包括 Payload、Headers、Exchange、Routing Key 等，且不会真正消费消息。

为什么需要它？

业务程序发送的消息进入队列后，你想确认消息内容是否正确、是否被正常投递，但又不想触发真实消费。探查功能通过 RabbitMQ Management API 抓取队列前 N 条消息并立即重新入队，满足这个需求。

怎么用？

  1. 点击侧边栏「消息」；
  2. 切换到「队列消息探查」标签页；
  3. 选择要探查的队列；
  4. 输入想查看的消息数量（1~100）；
  5. 点击「探查」按钮；
  6. 页面会显示该队列的待消费/处理中/总数/消费者数，以及消息列表和在线消费者信息。

图 4-11：队列消息探查页面——查看真实消息及在线消费者

提示：探查不会删除或消费消息，适合用来排查“消息到底长什么样”“有没有被投递到正确队列”。如果想看消息是否被消费、被谁消费，可结合「消费者列表」和「消费者工作室」进一步确认。

4.13 设置

是什么？

「设置」页面用于调整应用偏好和查看帮助信息。

为什么需要它？

你可以在这里切换界面主题、控制自动刷新、学习 RabbitMQ 术语、打开本操作手册。

怎么用？

图 4-12：设置页面

切换主题

  1. 点击侧边栏「设置」；
  2. 找到「外观」区域；
  3. 点击「浅色」「暗黑」或「跟随系统」；

自动刷新开关

  2. 打开/关闭开关；
  3. 选择刷新间隔（如 5 秒、10 秒、30 秒）；
  4. 总览页和队列列表会按此间隔自动拉取最新数据。

4.14 Management API 暂不可用提示新功能

是什么？

当 RabbitMQ Management API 访问失败（如网络断开、服务重启、认证过期）时，页面顶部会出现黄色警告横幅。

为什么需要它？

提醒你现在看到的数据可能是缓存，不是最新值，避免你根据过时的数字做判断。

怎么用？

看到横幅后，检查网络连接或 RabbitMQ 服务状态。恢复后，MQDesk 会自动刷新并隐藏横幅。

5. 常见问题解答

Q1：打开软件后提示“未连接到 RabbitMQ”怎么办？

原因：还没有选择或保存连接。
解决：点击侧边栏「连接」→「新建连接」→ 填写信息 →「保存并连接」。

Q2：测试连接提示“认证失败”怎么办？

原因：用户名或密码填错了。
解决：检查用户名、密码是否正确，注意大小写。如果不确定，可以询问提供 RabbitMQ 地址的同事或运维。

Q3：队列健康状态是红色，是什么意思？

含义：这个队列里有消息，但没有消费者在处理。
解决：检查对应的消费者程序是否启动，或者是否配置错误。

Q4：队列健康状态是黄色，是什么意思？

含义：这个队列的消息数超过了 1000 条，出现堆积。
解决：加快消费速度，或增加消费者实例。

Q5：发送消息后，状态一直显示“已发送”，不变成“已消费”？

原因：没有消费者程序处理这条消息。
解决：启动对应的消费者程序，或检查路由键是否正确。

Q6：关闭窗口后，MQDesk 还在运行吗？

答案：是的。关闭窗口会最小化到系统托盘，右键托盘图标选择「退出」才能真正关闭。

Q7：软件右下角没有托盘图标？

原因：Windows 可能把图标折叠到「显示隐藏的图标」区域。
解决：点击任务栏右下角的小箭头，找到 MQDesk 图标，拖到常驻区域。

Q8：界面出现「跳到主内容」字样？

答案：这是给键盘用户使用的无障碍快捷链接，按 Tab 键聚焦时会出现，平时不会显示。如果你一直看到它，请升级到最新版本。

Q9：暗黑模式下某些区域还是白色的？

原因：早期版本可能存在主题适配不完整。
解决：切换到浅色模式使用，或等待后续更新。

Q10：清空队列后消息数没有立即变成 0？

原因：RabbitMQ Management API 的统计信息有秒级延迟。
解决：稍等几秒再刷新，或观察自动刷新后的数字。

Q11：消费者工作室启动后看不到消息？

原因：队列里没有新消息，或过滤条件不匹配。
解决：确认队列有消息进入；检查过滤条件是否正确；切换为 preview 模式避免真实消费。

Q12：连接与信道页面为空？

原因：当前没有客户端连接到 RabbitMQ。
解决：启动一个生产者或消费者程序，刷新后即可看到连接。

6.2 术语解释

术语大白话解释
RabbitMQ一个负责在不同程序之间传递消息的软件
队列（Queue）存放消息的“桶”，消费者从这里取消息
交换机（Exchange）消息的“分拣中心”，决定消息该进哪个队列
绑定（Binding）交换机和队列之间的“连线规则”
路由键（Routing Key）贴在消息上的“地址标签”
消费者（Consumer）从队列取消息并处理的程序
待消费（Ready）已经躺在队列里、等着被取的消息
处理中（Unacked）已被取走但还没确认处理完的消息
虚拟空间（vhost）一块隔离的“房间”，不同项目互不干扰
AMQPRabbitMQ 用来传输消息的协议
信道（Channel）连接里的一个“虚拟通道”，大部分操作都在信道里完成
Prefetch消费者一次预取多少条消息，避免一次性压垮消费者
Ack消费者确认“这条消息我已处理完”
Purge清空队列里的所有消息，但保留队列
Publisher Confirm发送消息后，RabbitMQ 给的“收到回执”
Management APIRabbitMQ 提供的 HTTP 接口，MQDesk 通过它获取数据
