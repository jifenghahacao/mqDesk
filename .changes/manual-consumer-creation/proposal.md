# Proposal：MQDesk 手动消费者创建（Consumer Studio）

## 状态
- Status: Draft
- 提出者: AI Agent
- 日期: 2026-07-26

## 需求动机

用户需要在 MQDesk 中临时创建 RabbitMQ 消费者，用于：
- 消费测试消息验证队列投递是否正常
- 观察消息格式、头部、路由键等细节
- 在不写代码的情况下快速调试消费链路
- 控制消费生命周期（开始、暂停、继续、销毁）

## 功能范围（本次做）

| 需求 | 范围 |
|---|---|
| 消费者表单 | 名称输入、队列下拉选择、同步/异步模式、预览模式（默认手动 Ack，只看不消费）、可选真实消费模式、消息过滤条件 |
| 消息过滤 | 按 payload 包含/等于/正则匹配，以及 headers 键值对匹配 |
| 生命周期 | 创建 → 开始消费 → 暂停 → 继续 → 销毁 |
| 实时反馈 | 展示消费者状态（待启动/运行中/已暂停/已销毁/错误）和已消费消息列表 |
| 帮助提示 | 表单字段说明、空状态、错误提示 |
| UI 风格 | 复用现有液态玻璃设计，响应式布局 |

## 明确不做的边界（受 AGENTS.md / ADR 约束）

- **不改框架**：不替换 Preact/Tauri，不引入 React/Vue/Svelte。→ AGENTS.md 禁止项。
- **不破坏液态玻璃设计系统**：只使用现有 `tokens.css` / `glass.css` 变量，不修改核心 CSS 变量。→ AGENTS.md 禁止项。
- **不绕过 Tauri 命令**：前端不直接调用 RabbitMQ AMQP API，所有数据通过 Rust Tauri 命令转发。→ ADR 002。
- **不改动 `legacy/`**：旧项目归档仅作参考。→ AGENTS.md 禁止项。
- **不在 Tauri 命令层写业务规则**：消费者生命周期、过滤逻辑下沉到 `crates/core`。→ ADR 001。
- **不持久化会话消费者**：本次消费者为当前应用会话内有效，退出即销毁，降低复杂度。
- **不做消息编辑/重投**：仅消费并展示，不提供修改后重新发送到队列的功能。
- **不做消费速率图表**：消息列表按时间倒序展示即可，不绘制趋势图。

## 收益

- 测试人员无需编写代码即可验证队列消费链路。
- 运维人员可快速查看消息内容，辅助排障。
- 通过生命周期管理避免测试消费者长期占用连接或消息。
