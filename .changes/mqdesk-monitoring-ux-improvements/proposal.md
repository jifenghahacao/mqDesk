# Proposal：MQDesk 监控与安装体验优化

## 状态
- Status: Draft
- 提出者: AI Agent
- 日期: 2026-07-26

## 需求动机

用户在实际使用 MQDesk 过程中反馈 5 类问题：

1. **安装进度条视觉不一致**：NSIS 安装程序在解压大文件时，进度条显示百分比与视觉长度不匹配，给用户"安装卡住"的错觉。
2. **多连接状态辨识度不足**：连接管理页以卡片形式展示多个 RabbitMQ 配置，但卡片上未明确显示当前是否已连接，左下角的活动连接提示信息也较简略。
3. **集群节点监控缺失**：RabbitMQ 常以集群部署，当前系统仅展示当前连接节点的总览数据，用户无法通过单一入口查看集群内其他节点的运行状态。
4. **消费者信息不可见**：队列详情中缺少消费者 IP、消费速率、连接时长、订阅主题等关键排障信息。
5. **实施质量要求**：需要可验证的测试、文档，确保与现有架构兼容。

## 功能范围（本次做）

| 需求 | 范围 |
|---|---|
| 安装进度条 | 修复 NSIS 安装进度条百分比与视觉长度不一致问题；在 0%-100% 各阶段保持同步更新。 |
| 多连接状态 | 连接管理卡片展示每个配置的连接状态（未连接/已连接/连接中/失败）；左侧当前连接面板增加地址、协议、用户等身份标识；区分"配置"与"当前活动连接"。 |
| 集群节点监控 | 新增"节点"视图，通过已连接的 RabbitMQ Management API 拉取 `/api/nodes`，展示集群节点列表、节点名称、运行状态、Erlang 进程数、内存/磁盘告警、FD 使用量；不展示 CPU 占用率（Management API 不直接提供）。 |
| 消费者可视化 | 新增"消费者"视图，通过 `/api/consumers` 拉取消费者列表，展示消费者标签、channel 详情、连接主机/IP、订阅队列、ack 模式、预取值（prefetch count）；在队列详情页增加"查看消费者"入口。 |
| 测试与文档 | 为上述新增 Rust 命令添加单元测试；为前端视图添加 Vitest 组件测试；新增/更新用户操作手册章节；输出测试报告。 |

## 明确不做的边界（受 AGENTS.md / ADR 约束）

- **不改框架**：不替换 Preact/Tauri，不引入 React/Vue/Svelte。→ AGENTS.md 禁止项。
- **不破坏液态玻璃设计系统**：只使用现有 `tokens.css` / `glass.css` 变量，不修改核心 CSS 变量。→ AGENTS.md 禁止项。
- **不绕过 Tauri 命令**：前端不直接调用 RabbitMQ API，所有数据通过 Rust Tauri 命令转发。→ ADR 002。
- **不改动 `legacy/`**：旧项目归档仅作参考。→ AGENTS.md 禁止项。
- **不在 Tauri 命令层写业务规则**：集群/消费者数据解析、健康度判定下沉到 `crates/core`。→ ADR 001。
- **不引入新运行时依赖**：不引入数据库、缓存中间件；继续使用 reqwest + sled。
- **不做实时推送**：消费者/节点数据采用按需刷新 + 定时轮询（复用现有 overview 刷新机制），不新增 WebSocket/长连接。
- **不做跨 vhost 的集群节点详情编辑**：仅展示只读监控数据，不提供节点启停、配置修改等运维操作。

## 收益

- 安装体验更专业，减少用户"卡死"误报。
- 多连接场景下状态一目了然，降低误操作风险。
- 集群运维人员可快速识别异常节点。
- 队列消费异常时可通过消费者信息快速定位客户端。
